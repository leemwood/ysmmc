# 找服玩教程编写规范

统一找服玩关联教程的目标、章节结构、步骤、截图、下载安全、排错和维护要求，让玩家能够独立完成加入与配置。

## 教程目标

找服玩教程用于帮助玩家完成一个可以验证结果的任务，例如加入服务器、安装客户端、申请白名单、配置资源包或解决常见连接问题。

一篇合格教程应回答：

-   这篇教程要完成什么。
-   适用于什么平台和版本。
-   开始前要准备什么。
-   每一步具体怎么操作。
-   完成后如何判断是否成功。
-   失败时应该检查什么。

IMPORTANT

教程不是服务器宣传稿。宣传负责吸引玩家，教程负责让玩家安全、准确地完成操作。

## 服务器正文与教程怎么分工

| 载体 | 适合承载的内容 |
| --- | --- |
| 找服玩正文 | 服务器定位、玩法、版本、连接方式、规则、联系方式和最短加入路径 |
| 关联教程 | 需要多步完成的安装、配置、白名单申请、跨平台加入和排错 |
| 公告或更新帖 | 临时活动、维护通知、周目更新和短期变更 |

服务器正文不能只写“查看教程”。玩家在打开教程前，仍应知道服务器是什么、自己是否符合加入条件，以及最短加入入口在哪里。

## 适合单独编写的教程

-   Java 版首次加入教程。
-   基岩版或跨平台加入教程。
-   整合包、模组、资源包安装教程。
-   白名单或成员申请教程。
-   登录、绑定或角色验证教程。
-   常用菜单、领地、经济和任务系统入门。
-   延迟高、无法解析地址、版本不匹配等排错教程。

一篇教程只解决一个主要任务。Java 与基岩版步骤差异很大时，应拆成两篇或明确分节，不要让玩家在混合步骤中自行判断。

## 推荐结构

### 目标与适用范围

开头直接说明完成结果和适用环境。

```
本教程帮助 Minecraft Java 版玩家使用官方启动器加入方块原野，适用于 1.20.4。完成后你应该能进入大厅并看到新手指引。
```

### 准备工作

列出开始前必须具备的条件：

-   游戏平台和准确版本。
-   正版账号或其他登录要求。
-   必须安装的模组、整合包或资源包。
-   白名单、邀请码或社区账号要求。
-   预计下载大小和可用磁盘空间。

### 操作步骤

使用有序列表，一步只完成一个主要动作。

```
1. 打开 Minecraft 启动器，选择 `1.20.4`。
2. 进入“多人游戏”，点击“添加服务器”。
3. 在“服务器地址”中填写找服玩页面展示的连接地址。
4. 保存后选择该服务器并点击“加入服务器”。
```

界面名称、按钮、命令、文件名和路径应使用准确写法。命令和路径使用行内代码，不要仅用“点这里”“按图操作”等模糊表达。

### 成功验证

说明玩家如何确认操作完成，例如：

-   能看到服务器 MOTD 和延迟。
-   成功进入大厅。
-   资源包开始下载。
-   白名单查询页显示“已通过”。
-   指定命令返回正确结果。

### 常见问题

使用“现象、原因、处理方式”的结构。

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 客户端提示版本不兼容 | 使用了未支持的游戏版本 | 切换到教程标明的版本后重试 |
| 无法解析服务器地址 | 地址复制错误或本地 DNS 异常 | 从找服玩页面重新复制，并检查网络和 DNS |
| 显示未在白名单 | 申请尚未通过或游戏名填写错误 | 到官方申请入口核对状态和游戏名 |

### 更新时间与求助入口

教程结尾应注明适用版本或最近核对时间，并提供官方求助渠道。不要只留下个人私信入口。

## 步骤写作要求

-   按实际操作顺序写，不要先引用后面才会创建的文件或账号。
-   每一步说明动作对象和预期结果。
-   分支条件写在操作前，例如“基岩版玩家请跳到下一节”。
-   需要重启客户端或服务器时明确写出。
-   下载、解压、复制、覆盖和删除应分别说明。
-   危险或不可逆操作应提前说明影响和备份方法。
-   不假设玩家已经知道启动器目录、模组目录或服务器菜单位置。

## 截图与视频

截图用于帮助定位界面，不能替代关键文字。

截图要求：

-   截取与当前步骤直接相关的界面。
-   图片清晰，按钮和输入框可辨认。
-   在图片前后用文字说明要看哪里、做什么。
-   隐去账号邮箱、Token、后台地址、真实姓名和其他敏感信息。
-   界面更新后及时替换过期截图。

视频可以作为补充，但不能成为唯一教程。玩家应能只看站内文字完成关键步骤。

## 下载与安装安全

涉及启动器、整合包、模组或资源包时：

-   优先使用服务器官网、项目仓库或可信发行平台。
-   写明文件名、版本和用途。
-   能提供时附上文件大小和校验值。
-   说明文件应该放到哪个目录。
-   不要求玩家关闭杀毒软件、浏览器安全检查或系统防护。
-   不提供来历不明的可执行文件、破解账号工具或远程控制软件。

CAUTION

教程不得要求玩家提交 NexusMC 密码、API Token、邮箱验证码、2FA 验证码或 GeeID 凭据。白名单申请只收集完成审核确实需要的信息。

## 连接地址与隐私

如果找服玩页面公开显示连接地址，教程可以引导玩家从页面复制，避免在多处重复维护。

如果服务器选择隐藏连接地址：

-   教程只能引导到官方申请入口、QQ 群或 Discord。
-   不得在正文、图片、附件、视频字幕或评论中泄露隐藏地址。
-   应说明申请条件、处理方式和通过后从哪里获得地址。
-   不得诱导玩家私下购买地址或绕过白名单。

## 平台、版本与网络差异

教程中的版本信息必须与找服玩页面一致。使用代理或兼容插件支持跨版本时，应分别说明：

-   推荐版本。
-   可以进入但可能缺少功能的兼容版本。
-   Java 与基岩版的地址、端口和账号差异。
-   不同网络环境是否需要备用线路。

不要把单次测试成功写成“所有版本、所有网络都支持”。

## 教程关联条件

找服玩投稿通过 `tutorialPostIds` 关联站内帖子。教程要出现在服务器页面，必须同时满足：

-   帖子已审核通过，即状态为 `approved`。
-   帖子可见性为 `public`。
-   `accessMode` 为 `none`，不要求登录、回复或密码。

建议流程：

1.  先发布教程帖并等待审核通过。
2.  确认未设置额外访问限制。
3.  编辑找服玩投稿，在教程步骤中选择该帖子。
4.  保存或重新提交后，检查服务器页面是否显示教程。

教程后来变为非公开、增加访问限制或失去审核通过状态时，将不再作为有效关联教程展示。

## 维护与更新

以下变化发生后应同步更新教程：

-   服务器地址、端口或申请入口变化。
-   支持版本、启动器、整合包或模组列表变化。
-   白名单、正版验证或登录方式变化。
-   官网、QQ 群、Discord 或下载链接变化。
-   客户端界面和菜单发生明显变化。

重大流程变化时，在正文顶部标明旧教程不再适用，并尽快完成新版本。服务器停运后，应归档或更新教程，避免玩家继续下载失效文件。

## 常见反例

### 只有截图，没有文字步骤

问题：图片更新后无法搜索，也无法判断每一步的动作和结果。

### 只有群聊入口

```
不会安装就加群问管理员。
```

问题：教程没有解决任何操作问题，也无法长期维护。

### 把必要信息藏在回复或密码后

问题：受限帖子不能作为找服玩关联教程，玩家也无法在加入前判断流程。

### 要求关闭安全防护

问题：给玩家带来不必要的设备和账号风险。应提供可信下载来源并解释正常安装步骤。

## 提交前检查清单

展开检查清单

-   教程是否只解决一个主要任务。
-   适用平台、版本和前置条件是否明确。
-   玩家能否只看文字完成关键步骤。
-   每一步是否写明动作和预期结果。
-   下载来源是否可信，文件用途是否清楚。
-   是否包含成功验证和常见问题。
-   是否移除了密码、Token、验证码和隐藏地址等敏感信息。
-   教程帖是否公开、已审核且无访问限制。
-   链接、截图和操作名称是否仍然有效。
-   是否注明最近核对时间和官方求助入口。
