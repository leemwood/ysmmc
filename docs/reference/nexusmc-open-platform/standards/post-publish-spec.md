# 帖子投稿规范

说明帖子投稿时标题、板块、正文、普通帖、问答帖、投票帖、活动信息、标签、版权、可见性和访问模式的要求。

## 适用范围

这篇规范适用于 NexusMC 论坛普通帖、教程帖、说明帖、反馈帖、问答帖、投票帖和活动帖。

帖子投稿的目标是让读者在不反复追问作者的情况下，理解主题、上下文、证据和下一步行动。正式投稿前需完成 [创作者开通与协议确认](/docs/site-info/creator-onboarding/)。状态和错误处理见 [帖子投稿流程](/docs/operations/post-submission-flow/)。

## 先选择正确的帖子类型

| 类型 | 适合内容 | 不适合内容 |
| --- | --- | --- |
| 普通帖 `default` | 教程、说明、讨论、公告、反馈、作品展示 | 需要采纳答案或收集结构化投票的主题 |
| 问答帖 `qa` | 有明确问题、环境和可验证答案的求助 | 泛泛讨论、闲聊或没有具体问题的内容 |
| 投票帖 `poll` | 需要用户在明确选项中表达选择 | 用投票代替正文、诱导刷奖励或选项明显不完整 |

板块可能限制允许发布的帖子类型。草稿可以暂存部分类型数据，但正式提交时仍会检查目标板块是否支持该类型。

## 标题

标题应说明具体主题、对象和必要上下文。

推荐：

```
Paper 1.20.4 启动时报 UnsupportedClassVersionError
如何为资源帖编写可复用的安装章节
你更常用哪种 Java 版地图查看工具？
```

不推荐：

```
求助
有人吗
急急急
投个票
```

标题最长 200 字符，但不应把正文、标签和完整报错全部塞进标题。问题已解决或活动已取消时，更新正文和状态说明，不要把标题改成无法搜索的“已解决”。

## 板块与话题标签

板块决定帖子的读者、审核范围和可用类型。选择要求：

-   内容主题与板块职责一致。
-   不为了曝光重复发布到多个板块。
-   反馈、资源文档、活动和普通讨论进入各自对应板块。
-   没有目标板块发帖权限时，不通过相邻板块绕过限制。

普通标签最多 20 个，话题标签最多 5 个。话题标签必须属于当前板块允许范围；切换板块后应重新检查原有话题标签。

## 正文基本要求

正式提交时，正文必须达到站点当前最低长度。正文至少应包含：

-   主题背景或要解决的问题。
-   关键环境、版本或对象。
-   事实、步骤、截图、日志或来源。
-   作者希望读者采取的行动。
-   结论、当前进度或待确认事项。

不要只发布一张图片、一段群聊截图、一个外链或一句“如题”。外部链接可以补充证据，但站内正文必须自洽。

正文支持 Markdown 和部分 BBCode 兼容写法，具体范围见 [论坛正文语法支持](/docs/site-info/forum-markdown-bbcode/)。

## 不同内容的推荐结构

### 教程或说明帖

1.  目标与适用范围。
2.  环境、版本和准备工作。
3.  按顺序排列的操作步骤。
4.  成功结果和验证方法。
5.  常见问题与排错。
6.  最近核对时间或更新记录。

### 求助或反馈帖

1.  预期结果。
2.  实际现象。
3.  Minecraft、加载器、服务端、浏览器或系统版本。
4.  可复现步骤。
5.  完整错误信息和必要日志。
6.  已经尝试过的方法。

提交日志前删除 Token、Cookie、邮箱、IP、文件路径中的真实姓名等敏感信息。

### 公告或讨论帖

1.  事项背景。
2.  影响范围。
3.  生效时间或讨论截止时间。
4.  具体变化、可选方案或行动要求。
5.  联系人或后续更新位置。

## 问答帖

问答帖应提出一个可以判断是否解决的明确问题。正文建议包含环境、复现步骤、报错和已尝试的方法。

可以设置采纳奖励。设置奖励时：

-   奖励值应与问题难度和账号余额相匹配。
-   奖励大于 0 时必须存在有效积分类型。
-   采纳回答前应确认答案确实解决问题。
-   不得与其他账号串通发布、回答和采纳以转移积分。

问题解决后，应采纳最有帮助的回复，并在正文补充最终处理方式，方便后续搜索用户。

## 投票帖

投票必须提供 2 到 20 个去重后的有效选项。

| 设置 | 要求 |
| --- | --- |
| 单选 `single` | 每人只能选择 1 项 |
| 多选 `multiple` | 至少允许选择 2 项，最大选择数不能超过选项数量 |
| 结果公开时间 | 应使用明确时间，并在正文说明时区和用途 |
| 单人奖励 | 必须是可承担的真实奖励，不用于诱导无意义投票 |
| 奖励总预算 | 不能小于单人奖励，应与预计参与人数相符 |

选项应互斥或清楚说明可多选，不能用“同意”“非常同意”等模糊选项掩盖问题。重要决策还应提供“其他/补充说明”渠道。

切换帖子类型会清理不属于新类型的问答或投票数据，编辑前应确认是否真的需要切换。

## 活动帖

只有启用活动能力的板块可以填写活动信息。正式发布活动帖至少需要有效的开始时间。

建议同时填写：

-   活动标题和摘要。
-   开始与结束时间。
-   明确时区，默认按 `Asia/Shanghai` 理解。
-   线上地址或线下地点。
-   人数上限和是否开放报名。
-   活动封面、取消状态和后续通知方式。

结束时间不能早于开始时间。活动延期、取消或地点变化后应及时更新，不能只在评论区临时通知。

## 版权与来源

原创教程、长文、翻译和资料整理建议启用版权声明并选择准确许可证。

引用或转载时应：

-   标明原作者和来源链接。
-   区分原文、引用和自己的补充。
-   遵守原内容许可证和转载要求。
-   不删除水印、署名或版权说明。
-   翻译、整理和 AI 辅助内容仍需由投稿人核对事实并承担发布责任。

只贴原文、不注明来源，或把机器翻译和自动生成内容冒充原创，可能导致审核拒绝。

## 图片、代码与外链

-   图片应与正文直接相关，并配有必要说明。
-   代码块注明语言，保留能复现问题的最小上下文。
-   长日志只保留关键区段，完整文件可作为安全附件补充。
-   外链使用可信、稳定的 HTTPS 地址，避免多层跳转和短链。
-   不引导用户下载未知可执行文件、提交账号凭据或关闭安全防护。
-   不公开他人的私信、手机号、邮箱、IP 或未脱敏后台信息。

## 可见性与访问模式

帖子支持：

-   `public`：公开可见。
-   `partial`：仅指定用户可见，必须提供允许用户列表。
-   `private`：私密内容。

访问模式支持无额外限制、密码、回复后可见和登录后可见。使用时注意：

-   密码模式需要 4 到 64 字符的访问密码。
-   不要把标题、来源、版权或基础安全提示藏在访问限制后。
-   作为资源文档或找服玩关联教程的帖子，必须公开、已审核且无访问限制。
-   回复后可见不能用于强迫互动、隐藏无价值内容或绕过下载审核。

## 草稿、重复投稿与编辑

未完成内容应先保存草稿。草稿不公开，也不代表正式提交一定通过。

不要：

-   在多个板块重复发布同一正文。
-   把同一问题拆成多个缺少上下文的帖子。
-   审核通过后无痕替换成不同主题。
-   通过频繁编辑、改标题或改标签刷取曝光。

编辑已公开或已驳回帖子通常会重新进入审核。重大修正建议在正文保留更新说明，让读者知道哪些结论已经变化。

## 审核重点

审核人员通常会检查：

1.  标题、板块和帖子类型是否匹配。
2.  正文是否有足够上下文和实际信息。
3.  问答、投票或活动字段是否完整合理。
4.  标签、话题、版权和来源是否准确。
5.  图片、代码、日志和外链是否安全、必要且已脱敏。
6.  可见性和访问限制是否被合理使用。
7.  是否存在重复投稿、恶意引流、侵权、欺诈或违规内容。

## 投稿前检查清单

展开检查清单

-   标题是否说明具体主题。
-   板块和帖子类型是否正确。
-   正文是否包含上下文、事实和下一步。
-   问答是否有可验证问题，投票是否有完整选项。
-   活动时间、时区和地点是否有效。
-   标签和话题标签是否准确且不过量。
-   原创、转载、翻译和引用来源是否写清楚。
-   图片、日志和链接是否已检查安全与隐私。
-   可见性和访问模式是否符合用途。
-   是否避免重复投稿、无意义引流和审核后换题。
