# 找服玩首发规范

说明找服玩服务器首次发布时标题、分类、连接地址、版本、网络环境、正版验证、正文、图片和教程关联的填写要求。

## 适用范围

这篇规范适用于 Minecraft 服务器第一次提交到“找服玩”。无论从前台表单还是用户个人 API 投稿，都应满足相同的信息真实性和完整度要求。

首发的目标不是发布一张服务器广告，而是让玩家和审核人员能够判断：

-   服务器是否真实存在并可以连接。
-   支持什么平台、版本和网络环境。
-   是否开启正版验证，加入前还需要准备什么。
-   主要玩法、规则、收费项目和联系方式是什么。
-   服务器信息由谁维护，出现问题后去哪里求助。

正式提交前还需要完成 [创作者开通与协议确认](/docs/site-info/creator-onboarding/)。完整状态流程见 [找服玩投稿流程](/docs/operations/player-submission-flow/)。

## 标题与服务器身份

标题应以服务器实际名称为主体，可以补充一个简短玩法说明。

推荐：

```
方块原野 - Java 原版生存服
星港工坊 - 1.20.1 科技整合服
```

不推荐：

```
全网最好玩的服务器
开服送神装，进来就毕业
长期稳定永不关服
```

标题和正文不得冒充其他服务器、官方团队或合作方。以组织名义投稿时，应确认当前账号有权代表该组织维护服务器信息。

## 分类与简介

分类应反映服务器的主要玩法，不要为了曝光选择不相关的热门分类。多玩法服务器按长期核心玩法归类，其他模式可以在正文中补充。

简介用于列表页快速判断，建议一到两句话写清楚：

-   核心玩法。
-   适合的玩家类型。
-   最重要的加入条件。

```
面向休闲玩家的 Java 原版生存服，支持 1.20.4，需要正版账号并先阅读入服规则。
```

简介不要只写口号、群号、活动倒计时或“详情见群公告”。

## 平台、版本与网络环境

这些字段必须和服务器实际配置一致。

| 信息 | 填写要求 |
| --- | --- |
| 平台 | 明确 Java、基岩版或实际支持的平台，不要只写“全平台” |
| 支持版本 | 填写已经测试可进入的版本范围，跨版本兼容应说明代理或兼容方案 |
| 网络环境 | 至少选择一个实际可用的线路或网络环境 |
| 正版验证 | 必须如实说明是否开启在线正版验证 |
| 端口 | 填写玩家客户端实际使用的端口；Java 默认端口通常为 `25565` |

不要写“全版本通用”，除非已经验证主要客户端版本，并在正文中说明兼容边界。服务端核心、代理层或协议兼容插件可能允许跨版本进入，但不代表所有功能都正常。

WARNING

正版验证状态会直接影响账号安全和加入方式。离线模式服务器不得标记为已开启正版验证，也不能用模糊表述回避说明。

## 连接地址与加入入口

投稿必须向服务端提供可校验的公网服务器域名或 IP，即使选择对访客隐藏连接地址也不能省略。

连接地址要求：

-   填写 Minecraft 客户端使用的域名或 IP，不要填写网页地址。
-   端口必须在有效范围内，并与实际监听端口一致。
-   不得填写本机、局域网、保留地址或其他不可公开连接的目标。
-   不要使用随时失效的临时隧道或短链代替稳定地址。

如果服务器需要审核、白名单或邀请才能加入，可以开启“隐藏连接地址”。此时至少提供一种公开可用的申请渠道：

-   HTTP/HTTPS 连接申请页面。
-   QQ 群。
-   Discord。

申请入口必须说明审核方式和大致流程，不能只写“私聊服主”。教程和截图中也不得泄露原本选择隐藏的连接地址。

## 正文最低内容

服务器正文必须在站内自洽，不能只放官网、群聊或宣传视频链接。

至少应包含：

1.  服务器定位和主要玩法。
2.  支持平台、版本和客户端要求。
3.  加入步骤，或白名单申请方式。
4.  正版验证、网络环境和开放时间。
5.  主要规则与违规处理方式。
6.  管理团队或官方联系方式。
7.  付费、赞助、商城或增值项目说明。
8.  当前维护状态和信息更新时间。

如果需要整合包、模组、资源包或特定启动器，应提供安全、稳定的下载来源和安装教程。

## 玩法、规则与收费说明

玩法说明应能被实际进入服务器后的内容验证。不要把计划中的功能写成已经上线，也不要使用无法证明的在线人数、性能和稳定性数据。

规则至少说明：

-   是否允许作弊模组、辅助工具或自动化脚本。
-   是否有领地、交易、PVP、红石或刷怪限制。
-   封禁、申诉和举报入口。
-   重置周目、删档或重大规则调整的通知方式。

存在付费项目时，应提前说明商品类型、交付方式、有效期和售后渠道。不得用“完全免费”吸引玩家，再把必要功能放到付费项目中。

CAUTION

找服玩页面不是规避站内审核的广告跳板。收费、抽奖、赞助或外部商城信息仍需真实、清楚，并符合站点规则和适用法律要求。

## 封面与图集

封面和图集应展示服务器真实状态，例如：

-   出生点、主城和代表性建筑。
-   实际玩法界面、菜单或副本。
-   活动现场或真实游戏截图。
-   跨平台加入界面和客户端配置。

不应使用：

-   与服务器无关的网络图片。
-   只包含群号或宣传语的海报。
-   经过过度处理、无法反映实际画面的图片。
-   冒充在线人数、排行榜或玩家评价的合成截图。

自动图库会从正文提取图片；手动图库应只选择最能帮助玩家判断服务器的图片，避免重复上传相同画面。

## 教程关联

复杂的加入、安装或白名单流程应编写独立教程，并通过 `tutorialPostIds` 关联到找服玩页面。

可关联的教程帖必须同时满足：

-   状态为 `approved`。
-   可见性为公开。
-   不使用回复、登录、密码等访问限制。

教程内容要求见 [找服玩教程编写规范](/docs/standards/player-tutorial-style-guide/)。服务器正文仍要保留最短加入路径，不能把所有必要信息都移到教程帖。

## 可见性与访问限制

公开招募玩家的服务器通常应使用公开可见、无额外阅读限制的页面。如果使用部分可见、私密、回复后可见或密码访问，应有明确业务原因。

页面访问限制不会替代服务器自己的白名单、正版验证或账号审核。不要用“回复后可见”隐藏基础规则，也不要通过访问密码规避审核。

## 更新与维护责任

服务器首发通过后，作者仍需维护：

-   连接地址和端口。
-   支持版本与网络环境。
-   正版验证和白名单状态。
-   官网、申请入口、QQ 群和 Discord。
-   玩法、规则、收费项目和维护状态。

服务器停止运营、长期不可连接或不再接受新玩家时，应及时归档并说明原因，不要保留失效入口继续吸引访问。

## 审核重点

审核人员通常会按以下顺序检查：

1.  标题、分类和简介是否指向同一个真实服务器。
2.  地址、端口、平台、版本和正版验证是否自洽。
3.  正文是否足以完成加入并理解规则。
4.  隐藏地址时是否存在可用申请入口。
5.  图片、人数、玩法和收费说明是否真实。
6.  外链、下载和教程是否安全且能公开访问。

## 首发前检查清单

展开检查清单

-   标题是否使用服务器真实名称。
-   分类和简介是否准确。
-   平台、版本、网络环境和正版验证是否如实填写。
-   地址和端口能否从公网正常连接。
-   隐藏地址时是否提供有效申请入口、QQ 群或 Discord。
-   正文是否说明玩法、加入步骤、规则、收费和联系方式。
-   封面与图集是否来自真实服务器。
-   关联教程是否公开、已审核且无访问限制。
-   所有官网、下载和社群链接是否仍然有效。
-   停服、删档、重置和维护计划是否已经说明。
