# 快速开始

第一次进入文档中心时，从这里判断自己该阅读哪一类文档。

## 这是什么

这是 NexusMC 的帮助中心和文档入口，用来集中放置投稿流程、资源规范、用户个人 API 和后续站点规则。

如果你只是想完成一件具体事情，不需要从头读完整个文档中心。先按自己的目标选择路径即可。

TIP

第一次来文档中心时，先按目标跳转，不需要按左侧目录从上到下阅读。

## 文档怎么分类

当前文档现在更适合看成七类：

| 分类 | 内容 |
| --- | --- |
| 快速开始 | 帮助第一次进入文档中心的人找到入口，也说明文档维护方式。 |
| 站点机制 | 说明角色权限、用户等级、考试中心、创作者开通、身份认证、推广邀请、统计口径和常见问题。 |
| 账号与安全 | 说明账号绑定、密码、邮箱、手机号、通行密钥、2FA、登录设备和安全前置条件。 |
| 消息与通知 | 说明私信、聊天室、通知中心和未读处理。 |
| 投稿流程 | 说明帖子、资源、找服玩、视频从草稿到审核公开的流程。 |
| 资源规范 | 说明资源首发、更新和正文编写要求。 |
| 找服玩规范 | 说明服务器首发资料和关联教程的编写要求。 |
| 内容规范 | 说明视频首发和帖子投稿的内容质量、类型、来源与审核要求。 |
| API | 面向脚本、自动化工具和开发接入。 |

## 投稿相关状态

很多投稿文档都会提到状态。当前主要状态如下：

| 状态 | 含义 |
| --- | --- |
| `draft` | 草稿，仅作者可见。 |
| `pending` | 已提交，等待审核。 |
| `approved` | 审核通过，公开展示。 |
| `rejected` | 审核未通过，需要修改后重新提交。 |

如果你看到旧资料里写 `published`，在当前文档语境中应理解为 `approved`。

IMPORTANT

当前文档统一使用 `approved` 表示已审核并公开展示。脚本、文档和前台文案都不应混用 `published`。

## 推荐阅读顺序

如果你是普通用户：

普通用户阅读路径

1.  先读与你要投稿的内容类型对应的“投稿流程”。
2.  如果是资源，再读“资源规范”。
3.  想了解账号、等级、版主或统计口径时，再看“主站信息”。
4.  遇到报错时，先看对应流程文档里的“常见失败原因”。

如果你是脚本或工具开发者：

开发者阅读路径

1.  先完成开发者考试，创建只包含必要 scope 的个人 API Token。
2.  如果需要正式投稿，确认当前版本的创作者协议。
3.  阅读“用户个人 API”并接通最小请求。
4.  再回到对应投稿流程，理解状态和审核规则。

如果你是第三方站点开发者：

第三方登录接入路径

1.  先读“本站 OAuth2 接入”。
2.  让管理员创建应用并登记正确的回调地址。
3.  先接通 `authorize -> token -> userinfo` 最小闭环。
4.  最后再处理用户撤销授权、Token 过期和重新授权。

如果你是文档维护者：

文档维护者阅读路径

1.  先读“使用 MDX 编写文档”。
2.  新增内容时先选好分类和排序。
3.  写完后本地构建确认页面能生成。

## 文档更新原则

文档应以当前服务端真实实现为准。不要把规划中的能力写成已经开放的能力。

WARNING

不要把“计划支持”“后续可能开放”的能力写进用户操作流程。用户文档只写当前可用、可验证的行为。

写文档时优先回答：

-   用户现在能做什么。
-   需要准备什么。
-   失败时会看到什么。
-   应该怎么修正。
-   哪些能力当前不支持。
