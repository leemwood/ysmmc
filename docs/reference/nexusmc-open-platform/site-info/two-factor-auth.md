# 二步验证（2FA）

说明 2FA 的启用、关闭、备用码、验证码验证方式，以及它对登录和高风险操作的意义。

## 这是什么

二步验证（2FA）是在密码、OAuth 等登录方式之外，再增加一层动态验证码保护。

当前入口在：

```
/settings?tab=twofactor
```

按当前设置页文案，启用后密码登录和 OAuth 登录会要求输入动态验证码。

## 页面会显示什么

当前 2FA 分区主要分成两种状态：

| 状态 | 页面表现 |
| --- | --- |
| 未启用 | 显示“启用 2FA”按钮 |
| 已启用 | 显示状态、关闭入口、备用码剩余数量和备用码管理区 |

## 启用流程

当前标准流程是：

1.  进入“设置 -> 二步验证（2FA）”。
2.  点击“启用 2FA”。
3.  使用身份验证器扫描二维码，或打开 `otpauth` 链接。
4.  输入 6 位验证码。
5.  成功后系统生成备用码。

## 备用码

备用码是当前 2FA 体系里非常关键的一部分。

### 当前特性

| 特性 | 当前实现 |
| --- | --- |
| 数量 | 系统会生成一组备用码 |
| 使用次数 | 每个只能使用一次 |
| 展示方式 | 不会反复完整展示 |
| 下载 | 启用成功或重置后可下载 `.txt` 文件 |

IMPORTANT

备用码只适合在身份验证器不可用时应急使用。它们应该离线、安全保存，而不是放在随手可见的位置。

### 重置备用码

当前页面支持重置备用码，但需要先输入一次 2FA 验证码。

重置后：

-   旧备用码应视为失效
-   新备用码会重新生成并提示你下载保存

## 关闭 2FA

关闭时当前也需要输入一次 6 位 2FA 验证码。

关闭后：

-   账号不再要求 2FA 验证
-   现有备用码会被清理

如果只是更换手机或验证器，通常更好的做法不是直接关闭，而是先确认备用码和迁移方案。

## 2FA 和登录方式的关系

按当前实现，2FA 对不同登录方式的要求由站点设置决定，但当前前台文案明确强调了两类：

-   密码登录
-   OAuth 登录

而通行密钥登录本身通常已经是强认证路径，逻辑和 2FA 不完全一样。

## 2FA 和安全前置条件的关系

2FA 是当前站点认可的增强认证绑定方式之一。

这意味着：

-   绑定 2FA 通常可以满足很多“先绑定增强认证”的前置条件
-   某些高风险操作还可能要求你再次输入 2FA 验证码进行确认

相关说明见 [安全前置条件](/docs/site-info/security-prerequisites/)。

## 常见失败原因

展开查看 2FA 常见问题

| 场景 | 原因 | 处理方式 |
| --- | --- | --- |
| 扫码后验证失败 | 输入的 6 位码不正确，或时间不同步 | 检查身份验证器时间并重试 |
| 想关闭 2FA 但失败 | 验证码不正确 | 使用当前正确的 6 位码 |
| 下载备用码后没保存 | 备用码不会反复完整展示 | 立即离线保存，必要时重置备用码 |
| 重置备用码失败 | 当前输入的 2FA 验证码不正确 | 用最新有效验证码重试 |

## 疑难解答

### 备用码能代替 2FA 验证器一直使用吗？

不建议。它们是一次性应急手段，不是常规登录方式。

### 绑定了通行密钥，还需要 2FA 吗？

这取决于你的偏好和站点策略。两者可以同时存在；通行密钥偏便捷，2FA 偏通用，两者一起用也很常见。
