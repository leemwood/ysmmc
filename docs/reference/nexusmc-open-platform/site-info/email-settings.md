# 邮箱设置

说明当前绑定邮箱的查看方式、换绑流程、占位邮箱场景，以及修改邮箱时各步骤的校验逻辑。

## 这是什么

邮箱设置分区用于修改当前账号绑定邮箱。

当前入口在：

```
/settings?tab=email
```

## 当前页面做的不是“直接改一行字”

邮箱换绑当前是分步骤流程，不是简单输入一个新邮箱就立即改掉。

按当前实现，通常要经过这些阶段：

1.  查看当前邮箱
2.  验证当前邮箱
3.  输入新邮箱并发送验证码
4.  验证新邮箱验证码
5.  完成修改

## 当前绑定邮箱显示

页面会先显示“当前绑定邮箱”。

但如果账号是第三方登录占位邮箱，前台不会把它当成真正可用邮箱，而会显示：

```
未绑定可用邮箱（第三方登录）
```

这种情况下，流程会直接跳过“验证旧邮箱”那一步，转去让你填写新邮箱。

## 标准换绑流程

### 1\. 给当前邮箱发送验证码

如果当前邮箱可用，第一步是让系统发送验证码到旧邮箱。

### 2\. 验证当前邮箱

收到旧邮箱验证码后，输入 6 位验证码完成旧邮箱验证。

### 3\. 输入新邮箱

旧邮箱验证通过后，填写新的邮箱地址。

在某些站点配置下，这一步还可能要求先完成人机验证。

### 4\. 给新邮箱发送验证码

系统会把验证码发到新邮箱。

### 5\. 验证新邮箱并完成换绑

输入新邮箱收到的 6 位验证码后，邮箱修改完成。

## 占位邮箱场景

如果你的账号来自第三方登录，可能会遇到一种特殊情况：

-   当前账号没有真正可接收邮件的邮箱
-   系统用占位邮箱维持账号结构

这时邮箱设置页面会直接引导你补齐常用邮箱，而不是要求先验证一个本来就不可用的旧邮箱。

## 当前校验规则

按当前实现，邮箱换绑时至少会检查这些条件：

| 校验项 | 当前行为 |
| --- | --- |
| 新邮箱不能为空 | 为空会被拒绝 |
| 邮箱格式要正确 | 格式错误会被拒绝 |
| 新邮箱不能和当前邮箱相同 | 相同会被拒绝 |
| 新邮箱不能被其他账号占用 | 已占用会被拒绝 |
| 旧邮箱验证要先通过 | 普通换绑流程下必须先完成 |

## 修改成功后会怎样

当前完成换绑后，设置页会展示“邮箱修改成功”，并把当前邮箱显示更新为新邮箱。

但要注意：

-   换绑成功不等于一定已经完成新邮箱验证的全部外部策略要求
-   某些登录或通知功能仍可能受邮箱验证状态影响

## 和密码、Gee ID、通知的关系

邮箱不仅仅是联系方式，也会影响其他流程：

-   忘记密码和密码重置依赖邮箱
-   Gee ID 手机号绑定要求账号有可用于 Gee ID 的邮箱
-   部分邮件通知是否能正常送达，也取决于邮箱是否可用

## 常见失败原因

展开查看邮箱设置常见问题

| 场景 | 原因 | 处理方式 |
| --- | --- | --- |
| 旧邮箱验证码收不到 | 邮件功能未启用、投递失败或邮箱不可用 | 检查邮箱状态，必要时联系管理员 |
| 新邮箱验证码收不到 | 新邮箱投递失败或被拦截 | 检查垃圾邮件与邮箱可达性 |
| 新邮箱不能提交 | 格式不正确，或与当前邮箱相同 | 更换合法邮箱地址 |
| 系统提示邮箱已被使用 | 该邮箱已被其他账号绑定 | 换邮箱或处理原账号绑定 |
| 第一步直接跳到填写新邮箱 | 当前账号使用的是第三方登录占位邮箱 | 属于预期行为 |

## 疑难解答

### 为什么修改邮箱这么麻烦，还要验证两次？

因为邮箱本身就是账号安全要素之一。当前流程的目标是同时确认“你能控制旧邮箱”和“你也能控制新邮箱”。

### 我没有可用旧邮箱，还能改吗？

如果当前账号属于第三方登录占位邮箱场景，前台会直接走补齐新邮箱流程。
