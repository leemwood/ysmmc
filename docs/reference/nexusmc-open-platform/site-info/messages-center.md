# 消息中心

说明私信、聊天室、未读状态、消息撤回和“仅自己可见删除”的当前行为。

## 这是什么

消息中心用于集中管理两类实时沟通内容：

-   私信会话
-   多人聊天室

当前用户侧主入口是：

```
/messages
```

你也可以直接进入某个具体会话页面：

```
/messages/{conversationId}
```

## 当前支持什么

按当前实现，消息中心主要支持这些能力：

| 能力 | 说明 |
| --- | --- |
| 私信会话列表 | 展示最近消息靠前的私信会话 |
| 聊天室列表 | 展示管理员维护的聊天室及其未读数 |
| 实时收发消息 | 新消息会通过实时连接推送 |
| 未读计数 | 会话和聊天室都会显示未读数 |
| 标记已读 | 打开消息内容时可自动标记已读 |
| 消息撤回 | 私信支持发送后 2 分钟内撤回自己发出的消息 |
| 仅自己可见删除 | 前台支持把消息对自己隐藏，不影响对方看到 |

## 页面结构

当前 `/messages` 页面大致分为两列：

| 区块 | 作用 |
| --- | --- |
| 左侧列表 | 搜索会话、查看聊天室和私信列表 |
| 右侧聊天区 | 查看消息内容、输入并发送消息 |

移动端会在“列表视图”和“聊天视图”之间切换，不是桌面端那种一直双列展开。

## 私信怎么开始

当前常见方式是：

1.  进入某个用户主页
2.  使用“发消息”入口
3.  系统创建或复用你和对方之间的私信会话
4.  跳转到对应会话页

如果对方关闭了私信能力，创建会话时会被拒绝。

## 会话排序规则

当前私信和聊天室都会按“最近消息时间”排序。新的消息到达后，对应会话会自动靠前。

TIP

如果你觉得某个会话“突然跑到最上面”，通常不是异常，而是因为它收到了新的消息。

## 未读和已读

当前实现里有两层未读：

-   会话或聊天室自己的未读数
-   站点通知里的“私信通知”未读数

当你打开某个私信会话并按已读逻辑加载消息时，系统会：

1.  把该会话里的未读私信标记为已读
2.  清零对应会话未读数
3.  同步把关联的“私信通知”标记为已读

## 消息撤回

当前只有私信支持撤回，且限制比较明确：

| 规则 | 当前实现 |
| --- | --- |
| 谁可以撤回 | 仅消息发送者本人 |
| 时间限制 | 发送后 2 分钟内 |
| 撤回后的表现 | 内容改为“消息已撤回” |

撤回后，对话双方都会看到这条消息已被撤回，而不是直接消失。

## 删除和隐藏的区别

当前前台“删除（仅自己可见）”并不是把服务端消息彻底删掉，而是本地隐藏。

可以这样理解：

| 动作 | 实际效果 |
| --- | --- |
| 撤回 | 双方都看到“消息已撤回” |
| 删除（仅自己可见） | 只在你自己的前台视图里隐藏 |

IMPORTANT

如果你只是点了“删除（仅自己可见）”，不要把它理解成已经替对方删除了那条消息。

## 聊天室

聊天室和私信不同：

-   聊天室由管理员创建和维护成员
-   不是任意用户都能自己新建
-   会显示成员数、未读数和最近消息

它更适合固定范围内的多人交流，而不是一对一私信。

## 常见失败原因

展开查看消息中心常见问题

| 场景 | 原因 | 处理方式 |
| --- | --- | --- |
| 不能和某个用户发起私信 | 对方已关闭私信功能，或用户不存在 | 换其他联系渠道，或确认用户存在 |
| 打开发现没有消息 | 当前没有历史消息，或你在看的是新建会话 | 直接发送第一条消息 |
| 撤回失败 | 不是自己发的，或已超过 2 分钟 | 只能保留原消息或使用仅自己可见隐藏 |
| 删除后对方仍能看到 | 当前前台删除是本地隐藏 | 这是预期行为 |
| 会话未读数不变 | 还没有按已读逻辑进入消息内容 | 进入会话并正常加载消息 |

## 疑难解答

### 私信只有双方可见吗？

按当前用户提示和实现，私信属于双方会话内容，不是公开内容。

### 聊天室能自己建吗？

当前用户文档范围内，聊天室由管理员创建和维护成员，不是普通用户自助创建。

### 为什么消息区里会同时看到聊天室和私信？

因为当前消息中心就是把这两类沟通入口合并到同一个页面里管理。
