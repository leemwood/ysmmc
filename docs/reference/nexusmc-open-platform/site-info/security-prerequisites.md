# 安全前置条件

说明站点在哪些场景下会要求先绑定 2FA、通行密钥、双层密码或手机号，以及这些限制的区别。

## 这是什么

站点当前有一类“先满足安全条件，再继续操作”的机制。用户最常见的提示有两种：

| 提示类型 | 典型含义 |
| --- | --- |
| `SECURITY_SETUP_REQUIRED` | 需要先绑定二步验证（2FA）、通行密钥或设置双层密码 |
| `PHONE_BINDING_REQUIRED` | 当前访问地区需要先绑定手机号 |

这两种限制都属于前置条件，但触发原因不同，不应混为一类。

## 当前有哪些安全前置条件

### 1\. 增强认证绑定

增强认证指：

-   二步验证（2FA）
-   通行密钥
-   双层密码（二次密码）

当前账号设置入口分别在：

-   `设置 -> 二步验证`
-   `设置 -> 通行密钥`
-   `设置 -> 双层密码`

按当前实现，只要账号至少绑定或设置了其中一种，就满足“增强认证已绑定”的基本条件。

NOTE

双层密码属于账号密码体系下的增强，安全等级低于通行密钥。它可以作为部分安全绑定要求的兼容路径，但如果只设置了双层密码，没有 2FA 或通行密钥，一些高风险操作仍可能要求输入双层密码再次确认。

### 2\. 大陆手机号绑定

这是另一套独立门槛。当前实现中，如果：

1.  站点对某个动作开启了大陆手机号绑定要求
2.  你的当前访问地区被判定为中国大陆
3.  你的账号还没有绑定手机号

那么系统会阻止你继续执行该动作，并提示先去绑定手机号。

入口在：

```
设置 -> 手机号绑定
```

## 哪些场景可能要求先绑定安全认证

当前默认实现里，增强认证可能影响以下几类场景：

-   正式发布资源
-   正式发布帖子
-   发布找服玩内容
-   资源评论、找服玩评论、帖子回复
-   高风险评分行为
-   某些登录后或注册后的安全流程
-   需要重新确认身份的敏感操作

另外，一些高风险操作不只是“先绑定”这么简单，而是要求在操作前再做一次安全验证。

例如：

-   某些敏感设置变更
-   某些需要强确认的账号操作

这类场景通常会要求你输入一次 2FA 验证码、用通行密钥做一次确认，或输入双层密码完成确认。

NOTE

“已经绑定增强认证”解决的是是否具备资格；“重新完成一次安全验证”解决的是高风险操作前的再次确认。这是两个不同层级。

## 哪些场景可能要求先绑定手机号

按当前实现，手机号绑定策略可以单独作用在这些动作上：

-   发布资源
-   发帖
-   发布找服玩
-   发布视频
-   创建组织
-   发布资源评论
-   发布帖子评论
-   发布帖子回复
-   发布找服玩评论
-   发布视频讨论
-   修改个人简介
-   修改个人 README

是否真的启用，取决于站点当前后台设置。

## 当前访问地区是什么意思

手机号绑定策略不是单纯看账号资料，而是会参考“当前访问地区”判断。

按当前实现：

-   若当前访问地区不被判定为中国大陆，则这套门槛通常不会生效
-   若当前访问地区被判定为中国大陆，且对应动作已开启手机号要求，则会要求先绑定手机号

因此，同一个账号在不同地区访问时，看到的提示可能不同。

## 账号设置里分别去哪里处理

| 需求 | 页面入口 |
| --- | --- |
| 绑定 2FA | `设置 -> 二步验证` |
| 绑定通行密钥 | `设置 -> 通行密钥` |
| 设置双层密码 | `设置 -> 双层密码` |
| 绑定手机号 | `设置 -> 手机号绑定` |
| 查看第三方登录绑定 | `设置 -> 账号绑定` |
| 查看个人 API Token 是否开放 | `设置 -> API Token` |

## 和考试门槛有什么关系

安全前置条件和考试门槛是两套不同机制：

-   考试门槛决定你有没有资格使用某项功能
-   安全前置条件决定你在执行某项操作前，是否还需要补齐安全绑定

例如：

| 功能 | 可能同时受什么影响 |
| --- | --- |
| 个人 API Token | 先受开发者考试限制 |
| 推广邀请 | 先受入站考试限制 |
| 正式发布内容 | 可能同时受考试门槛、增强认证和手机号绑定影响 |

## 常见返回和提示

### `SECURITY_SETUP_REQUIRED`

常见返回示例：

```
{
  "error": "为保障账号安全，请先在设置中绑定二步验证(2FA)、通行密钥或设置双层密码后再执行此操作",
  "code": "SECURITY_SETUP_REQUIRED",
  "requireSecuritySetup": true
}
```

这表示要先完成 2FA、通行密钥或双层密码中的至少一种安全绑定。实际提示文案会随站点版本调整。

### `PHONE_BINDING_REQUIRED`

常见返回示例：

```
{
  "error": "当前访问地区需先绑定手机号后再执行此操作",
  "code": "PHONE_BINDING_REQUIRED",
  "requirePhoneBinding": true
}
```

这表示当前访问地区命中了大陆手机号绑定策略。

## 常见失败原因

展开查看安全前置条件常见问题

| 场景 | 原因 | 处理方式 |
| --- | --- | --- |
| 草稿能保存，正式提交失败 | 正式提交触发了增强认证门槛 | 先绑定 2FA、通行密钥或设置双层密码 |
| 发布页出现手机号提示 | 当前访问地区命中大陆手机号绑定策略 | 去设置页绑定手机号 |
| 已绑定密码，但仍提示安全绑定 | 普通登录密码不等于增强认证 | 绑定 2FA、通行密钥或设置双层密码 |
| 已参加考试，但功能仍被拦截 | 考试门槛已满足，但安全前置条件未满足 | 再检查 2FA、通行密钥、双层密码或手机号绑定 |
| 已绑定其中一项，某些敏感操作仍提示验证 | 当前操作要求再次完成安全确认 | 按页面提示输入 2FA 验证码、使用通行密钥或输入双层密码 |

## 疑难解答

### 绑定了密码，为什么还提示先完成安全绑定？

因为密码登录和增强认证不是同一个概念。当前安全门槛认的是 2FA、通行密钥或双层密码，而不是普通登录密码。

### 绑定了 2FA 之后，还需要绑定通行密钥吗？

不一定。按当前实现，只要至少有一种增强认证方式，通常就满足基础要求。通行密钥更多是额外的便捷和安全选项。

### 为什么只有部分操作要求手机号绑定？

因为手机号绑定策略是按动作单独配置的，不是全站所有操作一刀切。

### 管理员和总版主也受大陆手机号绑定限制吗？

按当前实现，管理员和总版主属于特权角色，不按普通用户的这套大陆手机号绑定门槛处理。
