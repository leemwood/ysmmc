# 通知中心

说明通知类型、筛选、已读/未读、清空操作和点击通知后的跳转规则。

## 这是什么

通知中心用于集中查看站内提醒。当前入口是：

```
/notifications
```

这里主要汇总：

-   回复
-   点赞
-   提及
-   私信提醒
-   系统通知
-   订阅和关注动态
-   审核或工作流相关通知

## 页面上有什么

当前通知中心主要由三部分组成：

| 区块 | 作用 |
| --- | --- |
| 顶部工具栏 | 切换筛选、全部标记已读、清空所有通知 |
| 通知列表 | 按时间倒序展示通知项 |
| 右侧统计 | 展示未读、今日、本周和全部通知数量 |

## 当前支持哪些筛选

按当前前台实现，通知中心支持这些筛选值：

-   `all`
-   `unread`
-   `reply`
-   `like`
-   `mention`
-   `message`
-   `system`
-   `subscribe`
-   `follow`
-   `moderation`
-   `workflow`

如果你只想快速清理未读，直接切到 `unread` 会更方便。

## 点击通知会发生什么

当前实现里，点击通知通常会先尝试把这条通知标记为已读，然后再跳转。

不同类型常见跳转规则如下：

| 类型 | 常见跳转位置 |
| --- | --- |
| 回复、提及 | 对应帖子或内容页 |
| 点赞、收藏 | 对应帖子或资源页 |
| 私信 | 对应会话页或消息中心 |
| 系统、审核 | 相关内容页，或后台审核/工作流页 |
| 订阅、关注 | 对应帖子、资源、找服玩、视频或用户页 |

## 已读、未读和统计

当前页面会维护这些统计口径：

| 统计项 | 含义 |
| --- | --- |
| 未读通知 | 当前还没有标记为已读的通知数 |
| 今日通知 | 从今天开始到现在产生的通知数 |
| 本周通知 | 最近 7 天通知数 |
| 全部通知 | 你的通知总数 |

通知列表和统计都会刷新，但不是每个数字都保证毫秒级同步。

## 全部标记已读

“全部标记为已读”会把你当前账号下所有未读通知统一改成已读。

适合的场景：

-   临时积压太多通知
-   你已经逐个处理过，只是不想再看到红点

它不会删除通知，只是改变已读状态。

## 清空所有通知

“清空所有通知”比“全部标记已读”更彻底。

| 操作 | 结果 |
| --- | --- |
| 全部标记已读 | 保留通知，只去掉未读状态 |
| 清空所有通知 | 直接删除你的全部通知记录 |

CAUTION

清空通知属于不可恢复操作。做完后，列表和统计都会被清掉。

## 和铃铛提醒的关系

导航栏里的通知铃铛和 `/notifications` 页面不是两套数据。它们都来自同一批站内通知，只是展示方式不同：

-   铃铛更偏向快速预览未读
-   通知中心更偏向完整整理和批量处理

## 常见失败原因

展开查看通知中心常见问题

| 场景 | 原因 | 处理方式 |
| --- | --- | --- |
| 打开页面没有通知 | 当前账号没有任何通知，或刚刚清空过 | 属于正常情况 |
| 点击通知没跳到目标页 | 目标数据已不存在，或该通知没有稳定跳转地址 | 回到对应内容入口手动查找 |
| 标记已读后数字没立刻变化 | 页面统计和未读数有短暂刷新延迟 | 稍后刷新或重新进入页面 |
| 清空后什么都没了 | 清空所有通知会删除记录 | 属于预期行为 |

## 疑难解答

### 通知和私信是一回事吗？

不是。私信是消息内容本身，通知里看到的“私信提醒”只是告诉你有新私信。

### 为什么我在通知里点了私信，会跳到消息中心？

因为私信通知的目标是把你带回对应会话或消息页，而不是在通知页里直接展开聊天。
