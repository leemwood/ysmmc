# 通行密钥

说明如何添加、命名、删除通行密钥，以及它和密码、强认证、安全前置条件之间的关系。

## 这是什么

通行密钥是基于设备生物识别、PIN 或系统凭据管理器的登录方式。

当前入口在：

```
/settings?tab=passkey
```

它的主要特点是：

-   登录时不必手输密码
-   可以作为增强认证绑定方式之一
-   某些情况下可以支持无密码模式

## 页面会显示什么

当前通行密钥分区会显示：

-   已添加的通行密钥列表
-   每个密钥的名称
-   添加时间
-   最后使用时间
-   是否为已同步状态

空状态下会提示你“还没有添加通行密钥”。

## 当前支持哪些操作

| 动作 | 说明 |
| --- | --- |
| 添加通行密钥 | 调用浏览器/系统的 WebAuthn 能力创建新密钥 |
| 重命名 | 修改你自己给这个通行密钥起的名字 |
| 删除 | 删除这把通行密钥，之后不能再用它登录 |

## 添加通行密钥的标准流程

1.  进入“设置 -> 通行密钥”。
2.  点击“添加通行密钥”。
3.  浏览器会调用系统认证器。
4.  完成指纹、面容或 PIN 验证。
5.  给这把通行密钥命名。
6.  创建成功后，它会出现在列表中。

如果你中途取消操作，页面通常只会提示“操作已取消”。

## 同步状态是什么意思

当前前台会把通行密钥大致分成两类展示：

| 状态 | 含义 |
| --- | --- |
| 已同步 | 通常表示这把密钥可通过系统或密码管理器同步 |
| 仅本设备 | 更偏向只存在于当前设备或当前认证器 |

这个标签是展示信息，不代表绝对的跨平台可用性承诺。

## 和密码的关系

通行密钥和密码不是互斥关系。你可以：

-   同时保留密码和通行密钥
-   先绑定通行密钥，再继续用密码
-   在满足条件时进入无密码模式

## 无密码模式

当前设置页支持一种“无密码模式”：

-   只有当账号已经绑定至少一个通行密钥时，才允许删除密码
-   删除后，你后续需要依赖通行密钥登录
-   以后如果想恢复密码登录，可以再回设置页重新设置密码

IMPORTANT

不要在没有稳定通行密钥方案时贸然删除密码。尤其是只绑定了一把、且只在单一设备上的通行密钥时，更要谨慎。

## 删除通行密钥会发生什么

删除后：

-   这把密钥不能再用于登录
-   如果你只剩这一把通行密钥，而又已经删除密码，可能会影响后续登录恢复

因此，删除前最好确认自己仍有至少一种可靠登录方式。

## 和安全前置条件的关系

通行密钥不仅是登录方式，也是当前站点认可的增强认证绑定方式之一。

这意味着：

-   有些高风险操作会要求你先绑定 2FA 或通行密钥
-   绑定通行密钥通常可以满足这层前置条件

相关说明见 [安全前置条件](/docs/site-info/security-prerequisites/)。

## 常见失败原因

展开查看通行密钥常见问题

| 场景 | 原因 | 处理方式 |
| --- | --- | --- |
| 页面没有“通行密钥”分区 | 站点未启用该功能 | 以当前站点配置为准 |
| 添加失败 | 浏览器不支持、系统拒绝、用户取消，或站点未启用 | 换受支持设备或重新尝试 |
| 删除后无法再用那把密钥登录 | 通行密钥已被移除 | 使用其他登录方式 |
| 想删密码却被拒绝 | 当前还没有绑定至少一个通行密钥 | 先添加通行密钥 |

## 疑难解答

### 通行密钥和 2FA 是同一个东西吗？

不是。它们都是增强认证手段，但实现方式不同。站点当前把它们都视为可满足安全前置条件的绑定方式。

### 我可以绑定多把通行密钥吗？

可以。当前列表和管理方式就是按多把密钥设计的。
